# Internationalisation

The public site speaks English (default, no prefix), French, Italian, Spanish and German. The back office speaks French only. French is the source language: the team writes in it, every other language is translated from it. English is the reference: always complete, and the fallback of the others.

## Where things are

| What | Where |
| --- | --- |
| Languages, default, cookie, `X-Locale` header | `packages/shared/src/i18n/locales.ts` |
| Address of each page in each language (`/fr/connexion`) | `packages/shared/src/i18n/pathnames.ts` (`PATHNAMES`, `localePath`) |
| Translated content types and helpers (`Translations`, `translated`, `staleTranslations`) | `packages/shared/src/i18n/translations.ts` |
| Names, flags, Open Graph regions of the languages | `packages/ui/src/i18n/locale.ts` |
| Texts of the site | `packages/ui/src/messages/{locale}.json`, `error-pages.{locale}.json` |
| Routing (next-intl, `localePrefix: "as-needed"`, `pathnames`) | `apps/frontend/src/i18n/routing.ts` |
| Navigation of the site: paths of the code, localized on the way out | `apps/frontend/src/i18n/navigation.ts` |
| Proxy: language and session redirects on the path of the code | `apps/frontend/src/proxy.ts` |
| Emails | `apps/backend/src/mail/templates/texts.ts` |
| Language of a request (`currentLocale()`) | `apps/backend/src/common/request-locale.ts` |
| DeepL, glossary | `apps/backend/src/translation/` |
| Translated content (fill, update, contexts) | `apps/backend/src/common/translations.ts` |

## Rules

- **Texts of the site.** Every text goes in the catalogs, never in a component. Write it in `fr.json` and `en.json` (both are required: `pnpm --filter @kilotrace/ui test` fails otherwise), then in the other languages; a text missing there falls back on English. The check also refuses a text that loses an argument (`{count}`) or a tag (`<b>`) of its French source. The site says « tu » in Italian, Spanish and German, « vous » in French.
- **Links.** Always the `Link` / `useRouter` / `redirect` of `@/i18n/navigation` (or `AppLink` / `useAppRouter` of `@kilotrace/ui/lib/navigation` in a shared component), with the path of the code (`routes.settings`, `/profiles?user=x`): they add the prefix and the address of the language. `usePathname` answers the path of the code. A new page gets its addresses in `PATHNAMES`, every language (TypeScript asks for them); without one, it keeps its English path everywhere.
- **SEO.** An indexed page sets `alternates: localeAlternates(locale, path)` in its metadata (canonical in its language, `hreflang` of the others, `x-default` English) and is listed in `app/sitemap.ts`. The layouts never set a canonical.
- **API.** The site sends `X-Locale` with every call (`lib/api/client.ts`, `lib/api/server.ts`); the backend keeps it for the request: `currentLocale()`. API errors are codes, translated by the site.
- **Accounts.** `users.locale` is the language of the emails and notifications: the one of the site at sign-up, then every change of the language menus while signed in. Signing in moves to it. `users.time_zone` follows the browser; the signed-in pages format their dates in it (`AccountTimeZone`), visitors in Paris.
- **Notifications.** Stored as a type and parameters, written by the site in the reader's language. A note of the team (a reason) is machine-translated for its reader when sent, the original kept (`originalReason`, shown on hover).
- **Content of the team.** Badges, collections and user tags keep their French in their columns and the other languages in `translations` (JSONB); release notes in `release_note_translations`. Each translation keeps the French it was made from (`translation_sources`, `sources`): when the French changes, the back office tells it « à revoir ». A public read picks the language of the request, then English, then French (`translated`). The back office edits them with `DetailTranslations` (`docs/admin-detail.md`).
- **DeepL.** `DEEPL_API_KEY` (free keys end with `:fx`). Every call tells DeepL what the text is (`TRANSLATION_CONTEXTS`, in French: an English context left names untranslated), uses the glossary of the site from French (`GLOSSARY`, one multilingual glossary: a free account keeps a single one) and the informal tone. `node dist/translation/fill-translations.js [--all]` in the backend container (`pnpm --filter backend translations:fill` in development) fills every field empty or out of date, or everything with `--all`.
- **Base map.** Its labels draw `name:<locale>` (`recolorStyle`); the back office maps stay in French.

## Adding a language

TypeScript lists most of the places: every map keyed by language is a `Record<Locale, …>` or `Record<TargetLocale, …>`.

1. `packages/shared/src/i18n/locales.ts`: add the code to `LOCALES` (`users.locale` holds 5 characters, `pt-BR` included).
2. `packages/shared/src/i18n/pathnames.ts`: the address of every page in the language.
3. `packages/ui/src/i18n/locale.ts`: its name in itself, its flag, its Open Graph region.
4. `packages/ui/src/messages`: `{locale}.json` and `error-pages.{locale}.json`, translated from French with the tone and words of the site (glossary below); run `pnpm --filter @kilotrace/ui test`. Then import the error pages in `apps/frontend/src/app/global-error.tsx`.
5. `apps/backend/src/mail/templates/texts.ts`: the emails.
6. `apps/backend/src/translation`: its DeepL code in `DEEPL_TARGETS` (check DeepL supports it, and its formality), its words in `GLOSSARY` (the glossary is created again at DeepL on the next translation).
7. `packages/ui/src/components/admin/detail/translations.tsx`: its tab label in French.
8. Rebuild `@kilotrace/shared` (the dev containers copy it: `docker cp` + `npx tsup`, or rebuild them), restart.
9. Translate the content: `fill-translations` in every environment, then have a native speaker read the catalogs and the main badges.
10. Check: the language menu, `/xx` and a localized address, `hreflang` of the home and the terms, the sitemap, an email (Mailpit), the map labels.
